# UI-ревизия и план улучшений интерфейса

Дата: 26.08.2026. Объект ревизии: визуальный слой приложения — `app/src/main/kotlin/ru/rfidhunter/app/ui/RfidHunterApp.kt` (1442 строки), `app/src/main/res/values/themes.xml`, `TriggerGif.kt`, `MainActivity.kt`.

Цель: привести интерфейс к виду «стильно, добротно, законченно» без изменения логики сценариев и устойчивого ввода.

---

## Диагноз: почему интерфейс выглядит прототипом

### 1. Не задана цветовая схема MaterialTheme (главная проблема)

`MaterialTheme(typography = roomyTypography)` в `RfidHunterApp.kt` не передаёт `colorScheme`, поэтому все основные кнопки («Открыть каталог», «Добавить голосом», «ПОДТВЕРДИТЬ», «ПОНЯТНО», элементы сервисного экрана) рисуются **базовым фиолетовым M3 `#6750A4`**, который конфликтует с захардкоженными синим/зелёным/оранжевым акцентами.

### 2. Нет дизайн-токенов

- ~20 цветов заданы hex-литералами прямо в composables: `0xFF1565C0` (синий названий), `0xFF2E7D32` / `0xFF66BB6A` / `0xFF1B5E20` (зелёные), `0xFFFFB74D` (оранжевый), `0xFFB71C1C` (красный), `0xFFF7F7F2` (фон), `0xFFE8F5E9` / `0xFFE3F2FD` (подложки) и т.д. Одни и те же роли дублируются разными значениями в 6+ местах.
- ~25 разных размеров шрифта инлайном (16–40 sp) без именованной шкалы.
- Высоты кнопок вперемешку: 60 / 64 / 72 / 78 / 82 / 88 / 96 dp.
- Радиусы без системы: пилюли `RoundedCornerShape(50)` против `12.dp` / `14.dp` у карточек и фото.
- Отступы между экранами различаются без причины.

### 3. Интерфейс полностью без иконок

Ни одной Material-иконки в пользовательском UI: все действия только текстом («ИСКАТЬ ВЕЩЬ», «УДАЛИТЬ», «ПЕРЕДЕЛАТЬ ФОТО»). Для пожилых пользователей иконка рядом с текстом служит важным визуальным якорем. Зависимость `material-icons-core` уже доступна транзитивно через material3.

### 4. Несогласованный «хром» приложения

- Статус-бар — тёмно-зелёный `#1B5E20`, навигация — чёрная, поверхность приложения — светлая `#F7F7F2`: три несвязанных цвета.
- Нет `windowBackground` под фирменный фон → белая вспышка при холодном старте.
- Заголовок «Искатель вещей» на Idle — просто текст, нет ни логотипа, ни фирменной графики.

### 5. Организация кода

- Весь UI (тема, общие компоненты, все экраны, сервисный экран, Geiger-логика отображения) живёт в одном файле `RfidHunterApp.kt`.
- Все русские строки захардкожены в Kotlin; в ресурсах только `app_name`.
- Большинство фотографий рисуются с `contentDescription = null`; баннер объявлений без `liveRegion`.

## План улучшений по приоритетам

### P0 — дизайн-система (даёт основную часть эффекта)

1. Определить фирменную `colorScheme` вокруг одного акцента (например, глубокий сине-зелёный вместо случайного микса фиолетового + зелёного).
2. Ввести семантические роли цветов и использовать их везде вместо литералов:
   - `success` — зелёный (ГОТОВО, ИСКАТЬ, статус «Слушаю»);
   - `warning` / edit — оранжевый (ИЗМЕНИТЬ, ПЕРЕДЕЛАТЬ);
   - `danger` — красный (УДАЛИТЬ, ошибки);
   - `info` / accent — синий названий вещей (`ThingName`);
   - surface/background — текущий тёплый `#F7F7F2`.
3. Именованная типографика: стили `screenTitle`, `thingName`, `sectionLabel`, `buttonLabel`, `bodyLarge`… вместо инлайн `sp`. Убрать ручные правки `lineHeight` из `withRoomyLineHeight()` — перенести значения в сами стили.
4. Токены формы и размеров: единая высота кнопки-пилюли (например, 84 dp), единый радиус карточек (например, 16 dp), шкала отступов (4/8/12/16/24).

### P1 — компоненты

1. Развить существующие обёртки `Button`/`OutlinedButton`: фиксированные роли (primary/success/warning/danger) и опциональная иконка слева от текста.
2. «УДАЛИТЬ» на карточке вещи сделать явно деструктивной (красная заливка или рамка + иконка корзины); сейчас это outlined с красным текстом — недостаточно выражено для защитного сценария подтверждения.
3. Баннер объявлений (`RfidHunterApp.kt:202`) оформить как скруглённый компонент с иконкой статуса вместо плоского зелёного прямоугольника.
4. Плейсхолдеры «Фото отсутствует» / «Фото» заменить на иконку изображения в тонированном круге; добавить полноценное пустое состояние каталога (иконка + подпись).
5. Экран «Вещь добавлена»: крупная анимированная галочка в зелёном круге вместо двух строк текста (экран показывается 3 секунды — анимация уместна).
6. `ReaderPreparationScreen`: README обещает этап «ищу → подключаю → готовлю» — визуализировать степпером из трёх точек/шагов, а не только строкой текста.
7. Idle: статус считывателя оформить компактной карточкой с цветной точкой состояния (готов / ищу / ошибка) вместо строки текста.

### P2 — брендинг и шрифт

1. Согласовать системные панели с поверхностью: светлые status/navigation bar либо единый брендовый цвет везде; `windowBackground = #F7F7F2` в теме.
2. Подключить открытый шрифт с кириллицей (Manrope / Rubik / Nunito) — округлый дружелюбный шрифт заметно повышает воспринимаемое качество для целевой аудитории; цена ~200 КБ в APK.
3. Простой логотип (RFID-метка / волны) рядом с заголовком на Idle.

### P3 — движение и отклик

1. Экраны меняются резко через `when` — обернуть переключение в `Crossfade`/`AnimatedContent` по `feedbackKey` с коротким переходом 150–200 мс (не мешает пожилым пользователям, убирает «дёрганность»). Гейт касаний (`TOUCH_GATE_DELAY_MS`) при этом сохраняется без изменений.
2. Лёгкий press-эффект на кнопках (scale/tonal) — опционально.

### P4 — порядок в коде

1. Разбить `RfidHunterApp.kt`:
   - `ui/theme/` — Color, Type, Theme;
   - `ui/components/` — кнопки, баннер, плейсхолдеры, сигнальная шкала, ThingName;
   - `ui/screens/*.kt` — по файлу на экран; сервисный экран отдельно.
2. Вынести русские строки в `strings.xml` или хотя бы в один объект констант.
3. Добавить `contentDescription` фотографиям и `liveRegion` баннеру объявлений.

**Не трогать при рефакторинге**: `resilientButtonInput`, `catalogCardTapInput`, гейт касаний (`ScreenUiPolicy.kt`), логику Geiger (`GeigerClickPlayer`, цикл щелчков), контракты safe-area (`UserScreen`).
