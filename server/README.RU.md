# Сервер резервного копирования RFIDHunter

[English version](README.md) · [Обзор приложения](../README.RU.md) · [Архитектура и протокол резервирования](../BACKUP_SYNC.md)

Сервер сохраняет резервную копию каталога RFIDHunter и восстанавливает её на другом телефоне. Приложение продолжает работать офлайн; резервирование включается в сервисном экране. FastAPI принимает изменения каталога и фотографии, SQLite хранит каталог и историю операций, а JPEG-файлы сохраняются на диске.

## Инженерные решения

- **Повторяемые изменения.** Каждое событие содержит `operationId`. Повтор того же события возвращает `already_applied`, а использование его ID с другим содержимым — `409 Conflict`. Устаревшие изменения получают статус `stale`, удаления сохраняются как отметки для восстановления.
- **Фотографии по содержимому.** Клиент загружает JPEG до отправки события каталога. Сервер сверяет SHA-256 тела с адресом запроса и повторно использует сохранённый файл при повторных загрузках.
- **Каталог переживает замену телефона.** Регистрация по паролю связывает первое устройство с аккаунтом. Восстановление подключает новый телефон к тому же каталогу и отзывает прежние устройства. Лимиты загрузки и доступ при восстановлении действуют на каталог аккаунта, включая данные с предыдущих телефонов.
- **Подписанные запросы.** Закрытый ключ ECDSA P-256 хранится в Android Keystore телефона. Сервер проверяет подпись, время, одноразовое значение nonce и права `UPLOAD`/`RESTORE`. Для паролей используются scrypt с солью и постоянный серверный секрет pepper; частота попыток регистрации и восстановления ограничена.

Транзакционная очередь Android, поля запросов и правила слияния при восстановлении описаны в [BACKUP_SYNC.md](../BACKUP_SYNC.md).

## Локальный запуск

Нужны Python 3.11+ и `uv`. Из каталога `server/`:

```sh
uv sync --dev
uv run python -m rfidhunter_server --host 127.0.0.1 --port 8080
```

Эти команды работают и в PowerShell. При первом запуске сервер создаёт `data/access_token` и `data/password_pepper`. Храните их вместе с серверными данными. В другом терминале проверьте доступность:

Bash:

```sh
rfidToken=$(cat data/access_token)
curl --fail "http://127.0.0.1:8080/$rfidToken/health"
```

PowerShell:

```powershell
$rfidToken = (Get-Content data/access_token -Raw).Trim()
Invoke-RestMethod "http://127.0.0.1:8080/$rfidToken/health"
```

Для телефона в той же доверенной локальной сети укажите LAN-адрес сервера в `--host`, а в приложении задайте адрес `http://SERVER_LAN_IP:8080/<token>`. HTTP принимают отладочные Android-сборки. Для развёрнутого сервера настройте HTTPS и полный адрес `https://backup.example/<token>`.

В сервисном экране приложения введите пароль длиной от восьми символов для регистрации каталога. На другом телефоне укажите тот же пароль и выберите восстановление. Участие администратора и код сопряжения не требуются.

## Настройка и развёртывание

Пути отсчитываются от рабочего каталога процесса. По умолчанию данные находятся в `./data`; этот каталог исключён из Git.

| Переменная окружения | Назначение |
| --- | --- |
| `RFIDHUNTER_DATA_DIR` | Основной каталог постоянных данных |
| `RFIDHUNTER_DATABASE`, `RFIDHUNTER_FILES_DIR` | Отдельные пути к SQLite и фотографиям |
| `RFIDHUNTER_TOKEN`, `RFIDHUNTER_TOKEN_FILE` | Секретный префикс URL или путь к файлу с ним |
| `RFIDHUNTER_PASSWORD_PEPPER`, `RFIDHUNTER_PASSWORD_PEPPER_FILE` | Секрет для поиска паролей или путь к файлу с ним |

Лимиты размера файла, объёма каталога и загрузок за временное окно задаются в [config.py](src/rfidhunter_server/config.py). Имя `RFIDHUNTER_MAX_STORAGE_BYTES_PER_DEVICE` сохранено для совместимости; этот лимит считается по всему каталогу аккаунта.

В репозитории есть [unit для systemd](deploy/rfidhunter.service) и [конфигурация HTTPS для nginx](deploy/rfid-nginx.conf). При развёртывании замените пользователя, пути, домен, сертификаты и шаблон `__TOKEN__`. Python-точка входа закрывает соединение, если первый запрос не содержит точного префикса токена; nginx также отбрасывает остальные пути. Префикс служит дополнительным ограничением пути, а подписи запросов подтверждают устройство. Для доступа к аккаунту и синхронизации используйте HTTPS.

Команды управления устройствами используют те же настройки данных, что и сервер:

```sh
uv run python -m rfidhunter_server --list-devices
uv run python -m rfidhunter_server --revoke-device DEVICE_ID
```

Резервирование самой серверной базы и удалённое файловое хранилище остаются будущими задачами.

## API и проверки

Все маршруты начинаются с настроенного префикса `/<token>`:

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Проверка доступности |
| `POST /v1/accounts/register` | Создание каталога и регистрация первого устройства |
| `POST /v1/accounts/restore` | Подключение нового телефона и отзыв прежних устройств |
| `PUT /v1/files/{sha256}` | Загрузка фотографии |
| `POST /v1/sync/events` | Применение изменения каталога |
| `GET /v1/sync/items?device_id=...` | Получение снимка каталога аккаунта |
| `GET /v1/files/{sha256}` | Скачивание фотографии из этого каталога |

Проверка доступности и доступ к аккаунту по паролю обходятся без подписи устройства. Для остальных запросов нужны `X-RFID-Device-Id`, `X-RFID-Key-Id`, `X-RFID-Timestamp`, `X-RFID-Nonce` и `X-RFID-Signature`.

Запустите существующие API-тесты из `server/`:

```sh
uv run pytest
```

14 тестов проверяют ограничение маршрутов, подписи и повтор nonce, изоляцию каталогов, хеши и лимиты файлов, порядок и идемпотентность событий, отметки удаления и восстановление на другом устройстве по паролю.
